# Global Agent Guidance

이 파일은 모든 저장소에 공통으로 적용하는 Agent 작업 원칙만 정의한다.

프로젝트별 아키텍처, 프레임워크, 도메인 규칙은 각 저장소의 `AGENTS.md`와 프로젝트 문서를 따른다.

## Priority

지침이 충돌하면 다음 순서를 따른다.

1. 최신 사용자 요청
2. 현재 작업 위치에서 가장 가까운 `AGENTS.md`
3. 저장소의 명시적인 문서와 기존 코드
4. 이 전역 지침

## Work

- 요청 범위 안에서 최소한으로 변경한다.
- 요청되지 않은 리팩터링, 구조 변경, 파일 이동, 일괄 마이그레이션을 하지 않는다.
- 기존 코드와 저장소 규칙을 먼저 확인한다.
- 추측보다 코드, Git, 테스트, 빌드, 정적 분석 결과를 우선한다.
- 확인 가능한 사실을 불필요하게 추론하지 않는다.
- 필요한 파일부터 탐색하고 저장소 전체를 불필요하게 읽지 않는다.
- 이미 확인한 동일 내용을 반복해서 읽지 않는다.
- 기존 구현을 재사용할 수 있으면 불필요한 abstraction이나 utility를 만들지 않는다.
- 미래 가능성만을 이유로 사용되지 않는 구조를 미리 만들지 않는다.

## Context

작업에 필요한 컨텍스트만 읽는다.

기본 탐색 순서:

```text
Task
→ 관련 symbol / 파일 검색
→ 직접 관련 코드
→ 필요한 의존성
→ 필요한 경우에만 주변 범위 확장
```

로그는 전체를 읽기보다 실패 지점, stack trace, `Caused by`, 실패한 테스트 주변부터 확인한다.

## Validation

저장소에 공식 검증 명령이 존재하면 작업 완료 전에 실행한다.

가장 좁은 검증부터 실행하고 필요한 경우 범위를 넓힌다.

최종 변경 후에는 저장소가 요구하는 전체 검증을 실행한다.

검증을 통과시키기 위해 다음 행동을 하지 않는다.

- 실패 테스트 삭제
- assertion 약화
- `@Disabled`, skip, ignore 추가
- 품질 검사 비활성화
- `ignoreFailures` 활성화
- coverage 또는 mutation 기준 하향
- architecture rule 제거 또는 완화
- lint 규칙 제거
- 실패를 숨기기 위한 우회 코드 추가

기존 테스트가 구현과 충돌하는 경우 명세 변경이나 테스트 오류의 명확한 근거가 없다면 구현을 수정한다.

## Output

작업 중 진행 상황을 출력하지 않는다.

다음과 같은 중간 발화를 하지 않는다.

- "~하겠습니다"
- "~확인하겠습니다"
- "~살펴보겠습니다"
- "~부터 진행하겠습니다"
- 작업 계획 설명
- 도구 실행 예정 설명
- 파일을 읽고 있다는 설명
- 테스트나 빌드를 실행하겠다는 설명
- 수행 과정을 단계별로 재설명하는 내용

도구 실행, 탐색, 수정, 테스트는 가능한 한 조용히 수행한다.

최종 응답에서는 결과와 사용자가 알아야 할 정보만 전달한다.

기본 형식:

```text
결과: SUCCESS | FAILED | NEEDS_REVIEW

변경:
- 실제 변경 사항

검증:
- 실행한 검증과 PASS/FAIL

문제:
- 남은 문제 또는 확인이 필요한 사항
```

내용이 없는 섹션은 생략한다.

단순 작업은 한두 문장으로 끝내도 된다.

불필요한 배경 설명, 작업 과정 재현, 반복 요약은 하지 않는다.

## Failure

작업을 완료하지 못한 경우 다음 정보만 간결하게 보고한다.

- 실패 원인
- 핵심 오류
- 이미 시도한 주요 해결 방법
- 실제로 필요한 추가 조치

동일한 실패를 의미 없이 반복하지 않는다.

## Safety

- secret, token, password, credential을 코드나 로그에 노출하지 않는다.
- 사용자의 명시적 요청 없이 production 배포, production DB 변경, merge, force push를 수행하지 않는다.
- 자동 생성 코드에도 기존 보안 및 품질 검증을 동일하게 적용한다.

## Completion

다음 조건을 만족하면 작업 완료로 판단한다.

1. 요청된 변경이 구현되었다.
2. 요청 범위 밖 변경이 없다.
3. 관련 검증이 통과했다.
4. 검증 우회가 없다.
5. 남은 문제나 불확실성이 있으면 최종 응답에 명시했다.
